ROU-213 / COF-009

Identity, driver, truck, and tax profile model

This is a manually maintained derived summary of the Core API profile-domain implementation. Canonical source remains the markdown contracts, data model, migrations, and service code.

What Changed

Core API now has the first authenticated profile model for app users, autonomous driver profiles, trucks, trailers, tax profiles, tax rule years, IPVA rules, compliance profile metadata, and insurance policy metadata.

Implemented API Surface

POST /api/drivers GET /api/drivers/me PATCH /api/drivers/me POST /api/trucks GET /api/trucks GET /api/trucks/{truckId} PUT /api/trucks/{truckId} POST /api/tax-profile GET /api/tax-profile

Affected Areas

Persistence

Flyway `V2__identity_driver_truck_tax_profile_model.sql` creates the profile-domain tables.

Core API

The `profile` package owns controllers, service logic, request validation, responses, JPA entities, and repositories.

Auth boundary

Authenticated principals are mapped to `app_users` records without implementing full login/session endpoints in this issue.

Compliance Boundary

RNTRC, CPF/CNPJ, plate, and RENAVAM values are app-maintained metadata and normal responses mask sensitive identifiers. Cofrete does not update ANTT, RNTRC Digital, Receita Federal, DETRAN, SEFAZ, SUSEP, insurer, gov.br, legal, tax, accounting, or official records.

Validation

`cd core-api && mvn -q validate test` covers schema validation and profile endpoint integration tests. `python scripts/agent_harness_check.py` covers repository guardrails and confirms this task explainer exists.

Unblocks

ROU-215 / COF-011 can now use real driver, truck, and tax profile inputs when implementing freight and trip profitability APIs.
