ROU-208 / COF-004

CI and PR harness guardrails are now first-class repository checks.

This change adds pull request validation, a PR template, and harness assertions so future service scaffolds inherit the same validation contract instead of relying on chat history.

1 GitHub Actions workflow for pull requests.
5 Service and infrastructure check groups documented for CI.
0 Service scaffolds required before this guardrail can pass.

What Changed

Pull request checks

.github/workflows/pr-checks.yml runs the agent harness and contains scaffold-aware Java, Node, and Docker Compose jobs.

PR template

.github/pull_request_template.md requires scope, validation, docs impact, finance and compliance caveats, UI evidence, and rollback notes.

Harness assertions

scripts/agent_harness_check.py now verifies the CI files, PR template, validation docs, and this explainer.

Validation Matrix

Area Command When It Runs
Repository harness python scripts/agent_harness_check.py Always.
Java services mvn -q validate test When a service has pom.xml.
Mobile app npm ci, npm run typecheck, npm run lint, npm run test:ci When mobile-app/package.json exists.
Web app npm ci, npm run lint, npm run test, npm run build When web-app/package.json exists.
Local infrastructure docker compose config When docker-compose.yml exists.

Why It Matters

  • ROU-209 and later service scaffold issues can add real build files without designing CI from scratch.
  • Finance and compliance PRs must explicitly state whether calculations, regulatory wording, or source documents changed.
  • The harness fails if CI, PR documentation, or validation guidance drift out of the repository.

Validation Run

Expected handoff validation for this task is python scripts/agent_harness_check.py. Service commands are documented and scaffold-aware but intentionally skipped until service source code exists.
