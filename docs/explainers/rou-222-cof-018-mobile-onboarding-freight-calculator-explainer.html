ROU-222 / COF-018 Mobile Onboarding and Freight Calculator

This manually maintained derived summary covers the mobile implementation for driver onboarding and the new freight profitability workflow. Canonical wording remains in docs/product/mvp-scope.md, docs/product/brazil-trucker-finance-blueprint.md, and docs/architecture/api-contracts.md.

What Changed

  • Added mobile driver and truck onboarding forms that call POST /api/drivers and POST /api/trucks.
  • Added a new freight calculator form for route, gross freight, loaded and empty kilometers, diesel assumptions, tolls, ARLA, direct costs, financing allocation, pass-through values, and payment timing.
  • Extended the mobile Core API client and TypeScript contracts to consume POST /api/trips, GET /api/trips/{tripId}, and POST /api/trips/{tripId}/profitability-estimate.
  • Added a profitability result screen that separates gross freight, pass-through cash flow, real trip cost, required reserves, expected profit, and safe personal withdrawal.
  • Added mobile tests for route rendering, conservative advisory copy, onboarding API submission, freight calculator happy path, and required input validation.
  • Added PRODUCT.md, DESIGN.md, and .impeccable/design.json so the frontend design workflow has durable product and visual-system context for future UI work.
  • Ran an Impeccable quality loop over polish, adapt, audit, harden, clarify, layout, and typeset passes.
  • Documented the end-of-task Impeccable review loop in docs/agent-harness/frontend-review-loop.md and wired it into the agent workflow for future frontend/mobile changes.

Why It Changed

ROU-215 introduced the backend trip profitability APIs. ROU-222 connects those APIs to the primary MVP mobile workflow: the driver enters freight and trip assumptions, sees deterministic planning output, and can decide whether to accept, reject, or renegotiate the freight.

Affected Areas

  • mobile-app/src/MobileApp.tsx: mobile onboarding and freight calculator UI.
  • mobile-app/src/api/client.ts: Core API client methods for driver, truck, trip, and profitability calls.
  • mobile-app/src/api/contracts.ts: mobile request and response types aligned with the API contract.
  • mobile-app/src/__tests__/MobileApp.test.tsx: mobile route, copy, validation, and workflow tests.
  • PRODUCT.md: durable product context for future Impeccable UI work.
  • docs/agent-harness/frontend-review-loop.md, docs/agent-harness/workflow.md, docs/agent-harness/validation.md, AGENTS.md, and mobile-app/AGENTS.md: future-agent workflow rules for end-of-task Impeccable loops.

Risk Boundaries

  • Calculator output is advisory planning output, not guaranteed earnings or professional financial advice.
  • Toll reimbursement and Vale-Pedagio are shown as pass-through cash flow and do not increase profit or safe personal withdrawal.
  • Profile data captured by Cofrete is app-maintained data and does not update ANTT, RNTRC Digital, gov.br, Receita Federal, DETRAN, SEFAZ, SUSEP, or insurer records.
  • The UI consumes the current API contracts but does not introduce authentication storage, secure credential handling, or production navigation beyond the MVP scaffold.
  • The Impeccable review loop is intentionally triggered only by frontend/mobile file changes, not backend-only or documentation-only tasks.
