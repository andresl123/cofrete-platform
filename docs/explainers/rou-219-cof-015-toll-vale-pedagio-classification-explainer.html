ROU-219 / COF-015 Toll And Vale-Pedagio Classification

Manually maintained derived summary. Canonical source of truth remains the Markdown docs and service code.

What Changed

  • Core API now exposes the contracted toll endpoints: POST /api/toll-estimates, GET /api/trips/{tripId}/tolls, POST /api/trips/{tripId}/tolls/manual-payment, POST /api/trips/{tripId}/vale-pedagio, and GET /api/toll-data/import-status.
  • Trip toll records store amount, payer, classification, finance treatment, confidence, source metadata, and receipt/proof references.
  • Vale-Pedagio records store provider/proof metadata, received status, derived classification, finance treatment, and confidence.
  • Trip profitability estimates use persisted toll classifications as defaults when request toll override fields are omitted. Pass-through, Vale-Pedagio, and identified included-in-freight toll components are excluded from profit; unknown tolls are treated conservatively as direct cost until reviewed.

Why It Changed

Toll reimbursement and Vale-Pedagio are pass-through cash flow. They can help explain cash movement, but they must not inflate expected profit or safe personal withdrawal.

Affected Areas

  • core-api/src/main/java/com/cofrete/coreapi/trip: toll entities, request/response contracts, service methods, and controller endpoints.
  • core-api/src/main/resources/db/migration/V6__trip_toll_vale_pedagio_model.sql: persistence for trip tolls and Vale-Pedagio records.
  • core-api/src/test/java/com/cofrete/coreapi/trip/TripEndpointTests.java: endpoint, classification, and deterministic profitability coverage.
  • docs/architecture/api-contracts.md and docs/compliance/vale-pedagio.md: classification semantics aligned with API behavior.
  • core-api/README.md: service status and endpoint summary.
