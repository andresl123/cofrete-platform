ROU-252 Waiting-Time Source Rules

Waiting-time charge assumptions now use a source-backed Core API rule and a deterministic Finance Worker calculator.

What changed

  • Added POST /api/source-rules/waiting-time for threshold/rate/effective-date configuration.
  • Added GET /api/source-rules/waiting-time to return the effective rule or explicit missing status.
  • Added waiting_time_rules with source URL, reviewed timestamp, freshness, and confidence.
  • Added WaitingTimeChargeCalculator for auditable excess-hours and ton-hour charge calculation.

Affected areas

  • core-api/src/main/java/com/cofrete/coreapi/compliance/
  • finance-worker/src/main/java/com/cofrete/financeworker/calculation/
  • finance-worker/src/test/java/com/cofrete/financeworker/calculation/WaitingTimeChargeCalculatorTests.java
  • docs/architecture/api-contracts.md
  • docs/architecture/data-model.md

Validation

cd core-api && mvn -q -Dtest=ProfileEndpointTests,ComplianceEndpointTests test passed.

cd finance-worker && mvn -q -Dtest=WaitingTimeChargeCalculatorTests test passed.

Risk boundary

Waiting-time impact is advisory. Copy explicitly tells drivers to confirm official rules and contract terms before charging or disputing a customer.
