ROU-215 / COF-011 Trip Profitability APIs

This manually maintained derived summary covers the Core API implementation for freight and trip profitability endpoints. Canonical wording remains in docs/architecture/api-contracts.md, docs/architecture/event-contracts.md, and related architecture docs.

What Changed

  • Added durable Core API records for freights, trips, trip cost inputs, profitability snapshots, acceptance decisions, and trip recalculation events.
  • Implemented the trip-first public workflow: create trip, read trip, request profitability estimate, read latest snapshot, and record acceptance decision.
  • Added advisory profitability math that excludes toll reimbursement and Vale-Pedagio as pass-through cash flow before calculating profit and safe personal withdrawal.
  • Added canonical trip.recalculation.requested event records and RabbitMQ publication using the contract routing key.
  • Added Core API tests for validation, persistence, snapshot behavior, acceptance decisions, and canonical event fields.
  • Documented the temporary Core API synchronous estimate decision in docs/adr/0002-temporary-core-api-trip-estimates.md.

Risk Boundaries

  • Profitability output is advisory planning data, not legal, tax, accounting, insurance, ANTT, ANP, DETRAN, SEFAZ, or payment guidance.
  • Pass-through cash flow is visible but does not inflate expected profit or safe personal withdrawal.
  • Core API owns only the temporary synchronous estimate path; Finance Worker remains the long-term async profitability calculation owner.
  • RabbitMQ publication is part of the recalculation request path so Finance Worker can recalculate from authoritative Core API trip state.
