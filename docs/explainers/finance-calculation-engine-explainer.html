ROU-216 / COF-012 Finance Calculation Engine

Implemented a deterministic Finance Worker engine that turns an explicit trip finance snapshot into advisory money outputs for a Brazilian truck driver.

Canonical details live in docs/architecture/finance-calculation-engine.md. This page is the concise handoff.

What Was Added

  • A pure calculator: TripFinanceCalculator.calculate(input).
  • Input and output records for trip finance snapshots, reserve policy, trace entries, and health impact.
  • Event handling for trip.recalculation.requested.
  • Publication of trip.finance.recalculated with decimal-string monetary values, correlation ID, idempotency key, and source freshness.
  • Fixture-based tests proving stable output for fixed inputs.

Calculation Logic

The calculator uses only the input snapshot. It does not read time, database state, environment variables, network services, or random values.

fuelCost = totalDistanceKm / dieselConsumptionKmPerLiter * dieselPricePerLiter passThroughAmount = tollReimbursement + valePedagio + otherPassThrough reserveBase = grossFreight - passThroughAmount directTripCost = fuel + arla + nonReimbursedToll + mealsAndLodging + otherDirect requiredReserves = reserveBase * each configured reserve rate, rounded per bucket expectedProfit = grossFreight - passThroughAmount - directTripCost - requiredReserves - financingAllocation safePersonalWithdrawal = max(expectedProfit, 0.00)

Toll reimbursement and Vale-Pedagio are pass-through money. They are visible in the output but excluded from profit.

Event Flow

  • Listener receives trip.recalculation.requested.
  • Service validates event type, version, required IDs, producer, correlation ID, and timestamp.
  • Duplicate requests are suppressed by idempotencyKey.
  • The service loads a matching TripFinanceInputSnapshot.
  • The pure calculator produces the result.
  • Publisher sends trip.finance.recalculated.

Important Boundary

trip.recalculation.requested contains IDs and inputRevision, not full money inputs. The worker now exposes TripFinanceInputSnapshotProvider for a future Core API or read-model integration.

The default provider fails explicitly. That is intentional: production must not fabricate finance results without authoritative trip inputs.
