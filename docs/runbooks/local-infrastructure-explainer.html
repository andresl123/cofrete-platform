ROU-207 / COF-003

Local infrastructure for backend and worker development

This task adds the disposable Docker Compose stack that unblocks Core API and worker scaffolding: PostgreSQL, RabbitMQ, MinIO, shared networking, documented ports, health checks, safe local defaults, and service connection placeholders.

Changed

Runtime stack

  • docker-compose.yml defines PostgreSQL, RabbitMQ, MinIO, MinIO bucket init, named volumes, and the cofrete-local network.
  • .env.example provides safe local defaults and placeholders for core-api, finance-worker, and data-importer-worker.
Documented

Runbook

  • docs/runbooks/local-development.md now covers startup, reset, health checks, ports, common failure modes, and synthetic-data boundaries.
  • Service READMEs list container and host connection placeholders for upcoming scaffolds.
Guarded

Validation

  • scripts/agent_harness_check.py now requires the Compose file, env example, runbook markers, service placeholders, and this explainer.
  • The required local validation commands are docker compose config and python scripts/agent_harness_check.py.
Why

What this unblocks

ROU-209 / COF-005 can now scaffold the Core API against a documented local PostgreSQL profile and a shared Compose network. Finance and data-importer worker scaffolds can use the same RabbitMQ and MinIO conventions without inventing separate local dependency contracts.

Boundary

Local only

The stack is intentionally disposable. Production remains Kubernetes, credentials stay outside Git, and local data must be synthetic unless an official source is explicitly documented.
